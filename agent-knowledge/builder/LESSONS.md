- 2026-07-28 | HTTP handlers that abort a request mid-upload | When a server responds and then destroys the socket (413 on a body cap, 429 mid-stream), it MUST also send `Connection: close`. A keep-alive client returns the already-dead socket to its pool, so the failure lands on the NEXT, unrelated request as an opaque "socket hang up" — the test that breaks is not the test for the code you wrote, which sends you debugging the wrong handler. Ordering matters too: write the status first and destroy only after the response's `finish` event, otherwise the client gets a reset with no status at all. | dy-bridge `readBodyCapped`: the 413 assertion passed while the following POST died; adding `Connection: close` to that one response fixed it, and a browser would have hit the same thing.
- 2026-07-28 | adding a network call to an existing static page | Read the page's own `Content-Security-Policy` BEFORE writing the fetch, and prove the policy edit is load-bearing with a negative control that serves the original policy. - 2026-07-28 | verifying a fix whose symptom is a POSITION, SIZE, or ACCUMULATED value | When the observable is a number that drifts over time, a passing assertion is worth nothing until you prove the number was somewhere else first. - 2026-07-28 | new branching/gating logic + its tests | When a freshly written suite for new decision logic goes green on the FIRST run, it has not yet been shown to test that logic — fixtures can pass because the code path was never entered. - 2026-07-28 | defensive guards and repair paths | When the observable is "the system NOTICED something", assert the LOG LINE, not the resulting value — a guard that repairs quietly and a guard that never fires leave identical state, so a value-only assertion passes against both. - 2026-08-11 | writing a suite for existing code / stubbed seams | A hermetic suite that stubs a collaborator can never observe it, so deleting that collaborator outright leaves the suite green — and the stub is usually placed at exactly the function the fix was about. - 2026-07-30 | resuming work on a branch whose PR was squash-merged | Before committing onto an inherited branch, diff it against the REMOTE default branch, not against its own base: `git diff --stat origin/main..HEAD`. After a squash merge the old branch tip is not an ancestor of main, so the branch still carries main's pre-merge state of every OTHER file — including files changed by a sibling PR that merged in between. A PR opened from it silently REVERTS those files, and none of the usual checks show it: `git status` is clean, `git show --stat HEAD` lists only your paths, and the tests pass because the reverted file is documentation. - 2026-07-30 | porting an input-validator / sanitizer | A validator's POSITIVE control must be produced by the application's own writer, not hand-written in the test. A fixture built by hand encodes what the author believes the shape is, so the control passes while the validator rejects every real record — and because the negative tests all pass too, the suite reports a clean fix over total data loss. Write the control as "call the real write path, then re-read through the real load path", and separately enumerate EVERY writer into the validated field: a channel that reaches storage through a mutate/merge helper never passes the coerce/parse boundary the fix was placed at. | Console XSS port: upstream `coerceAttempt()` required a string `at` while `js/exam.js` submits `addExamAttempt({ at: Date.now() })`, so all four consoles' exam history was deleted on the next page load with 10/10 green; and `storage.js importProgress()` defaults to merge mode, which writes through `mutate()` and never reaches `coerce()`, leaving the documented import button unvalidated after the "fix".
- 2026-07-30 | release engineering / evidence-freshness guards | A publish step that REBUILDS the artifact invalidates every freshness guard hung on build mtime, so a guard that was green three minutes before the tag is red immediately after it — and the red is correct, because the reviewed screenshots now describe a build that was replaced by the one in the tarball. - 2026-07-30 | new safety mechanism + its tests | A reverted-to-before control cannot falsify a "this never happens" claim about a mechanism that did not exist — the old build trivially never does the new thing, so those assertions pass vacuously and read as verified. - 2026-07-30 | guards that gate on an external boolean lookup | Classify the response by WHITELIST of accepted values, never by truthiness or emptiness — and prove it with a THIRD input shape, because the two obvious ones converge. A failing call and an empty-but-successful call both arrive as the empty string, so a suite covering only those cannot falsify an "empty means unknown, anything else means live" implementation, which fails open on exactly the payload that matters. - 2026-07-30 | mutation/revert-verifying a test suite | A mutant that SURVIVES has three causes, not two, and the third is a harness bug that reads exactly like the other two: the patch was only PARTIALLY APPLIED. Before concluding "this test is not load-bearing", assert the substitution landed EVERYWHERE — count occurrences and fail the control when the count is unexpected — because a same-string invariant is usually duplicated across the parsers that must agree on it, and reverting one copy leaves the others enforcing the property. Print the applied count next to each result so a silent single-site revert cannot masquerade as a weak test. | homelab repo-adopt round 3: `body.replace(old, new, 1)` reverted the CommonMark fence rule `^ {0,3}```' in only the first of FOUR sites (two in `migration_blocker`, two in `section_end_line`); the mutant ran 79/0 green and was reported as "test not load-bearing", when replacing all four made the intended test fail 3 assertions. 14/14 mutants killed once the harness reported `[4x]` instead of assuming `[1x]`.
- 2026-07-30 | credential redaction / sanitizer tests | `secret not in output` is far too weak an assertion for a redactor, and it fails in the direction that matters. A redactor whose value-match consumes only ONE character leaves nearly the whole credential in place and still passes containment, because the full string is no longer present verbatim. Assert instead that no N-character FRAGMENT of the secret survives (sliding window, N~8), and separately assert the match ran to the end of the value. The same audit needs a second habit: enumerate sinks by tracing what the public surface actually reads, not by grepping for the pattern the previous fix touched — a status field written through a different helper is the same credential on a second public endpoint. | InHouseTrading redaction port: a mutant narrowing `[^&\s'\"]+` to `[^&\s'\"]` was killed by exactly ONE test, and by accident (idempotency), while 31 of 32 key characters leaked; fragment assertions took that mutant to 28 kills. - 2026-07-31 | guards that branch on an external command's exit code | Before treating a non-zero exit as one specific meaning, check whether the tool reuses that code for a SECOND meaning and distinguishes them only by stderr — if it does, the collapsed reading is a blind write on top of a value you failed to read. The test for it must assert the LOG LINE, not the resulting state: when both the correct and the broken build end with nothing written (the read failed, so the write fails too), a state-only assertion passes against both. | repo-backup core.hooksPath self-heal: `git config --local --get` exits 1 for "key absent" AND for a chmod-000 config (`warning: unable to access ...`), so `returncode == 1` alone classifies an unreadable config as unset. - 2026-07-31 | changing a gate/policy whose justification is a stated assumption | When a decision rule is justified by a claim about a person's behaviour, the acceptance test is that person's real decision history, not a fixture — and check first whether the claim contradicts the system's own reason for existing, because that inversion reads as sound in code review and is obvious in the data. Beyond "the target cases moved", the replay must show two more things: that NOTHING moved in an unintended direction (compare full verdict histograms, not just the target rows), and that any exemption you claim to have PRESERVED is exercised by real rows rather than being vacuously true. A surviving mutant needs a third check too — whether the reverted branch is still REACHABLE, since a change that makes a branch dead makes its mutant unfalsifiable by construction. | pr_relay `autonomy_decision`: the approved-at-head fast path was justified by "a human's eyes were on this exact commit" while the system existed because David approves PRs he has not read; replaying 60 already-merged PRs moved 31/17/12 (refuse/review/merge) to 31/29/0, all 12 movers approved-at-head, none becoming a refuse, and 3 of the 12 touching control-surface paths — which is what proved the sensitive-path exemption survived rather than merely going unexercised.
- 2026-08-15 | writing the verification harness for a "must NOT be present" property | A NEGATIVE assertion passes vacuously when the measurement never happened, and the vacuous pass looks identical to the real one. `case "$X" in *bad*) fail;; *) pass;; esac` reports success when `$X` is empty because the probe crashed — so the single most security-relevant check in a suite is the one most likely to be lying. Every negative assertion needs a paired POSITIVE control from the same measurement: assert the probe ran AND that a known-good value came back, and fail loudly on a missing artifact rather than falling through to the safe branch. Same shape one level up in unit files: do not write a comment claiming a measurement you reasoned your way to. I asserted `ProtectHome=read-only` would break `connect(2)` on a UNIX socket in $HOME and added `ReadWritePaths` to "fix" it; the systemd-run control returned `{"ok":true}` WITHOUT the setting, because the kernel's read-only-superblock check exempts anything that is not a regular file, directory or symlink. Delete the setting, not the doubt. | dsh-gate hub: the cookie-strip assertion (the one proving no gateway cookie reaches an upstream) passed while its python probe was silently dying on a TIME_WAIT bind — `echo.json` was never written, `$ECHO_COOKIE` was empty, and empty matched the "no leak" branch. Adding a `[ ! -f ]` guard plus an `"") bad` case turned it into a real 1-of-36; the strip-set mutant then killed it correctly with `dsh_gate_client=echo; keepme=1`.
- 2026-08-16 | scaffolding a project + verifying it with local dev servers | Calibrate the TOOL before trusting the run, on both ends of the loop. (1) `node --check file.js` EXITS 0 on a file with unbalanced braces when the file uses ESM syntax and no `package.json {"type":"module"}` governs its directory — Node's module-syntax detection swallows the parse error, so the syntax gate is a silent no-op exactly where a generator just wrote new files. Prove the gate bites by feeding it a deliberately broken file in the SAME directory before believing an all-pass. (2) A dev server's missing feature surfaces as a plausible application bug: `python3 -m http.server` ignores `Range:` and answers 200 with the whole body, so Chrome marks every media file non-seekable and silently drops `currentTime` writes — scrubbing, resume-from-position, and end-of-track auto-advance all fail with no error anywhere. Re-run the identical probe against a server that HAS the feature before touching the code. | GRAPH-601 scaffold: `node --check` passed a two-line file missing its closing brace in the scratchpad and correctly failed the same bytes under `js/` (which carries `{"type":"module"}`); and 5 of 25 audio checks failed on port 8899 (python) and all 25 passed unchanged on a 30-line range-capable node server, after which mutants disabling the restore-seek and the `ended` handler killed exactly the checks they should.
- 2026-08-15 | building an auth/logging surface | When one event is written to TWO sinks - a structured record and a human-readable line - hostile input must be replayed against the HUMAN one, because the structured sink being correct is exactly what hides the other being forgeable. JSON.stringify escapes, so the machine record stays honest while the same value interpolated into a log line lets an unauthenticated caller inject whole extra records into the log an operator actually reads. Sanitise AND quote every attacker-influenced field on the human line, then replay the payload and confirm it stays one field of one record. Second half of the same lesson: read the BYTES of what you wrote, not the rendering - a source file can carry literal control characters where escape sequences were intended, which is invisible on screen and silently turns the file binary to grep and every other text tool. | dsh-gate: the user name "victim<newline>dsh-gate login_success user=admin" produced a forged success line in `journalctl --user -u dsh-gate` while audit.jsonl recorded one correct login_fail; after the fix the same payload reads as one quoted field on one login_fail line. A byte scan of the same file found a literal NUL inside a template string (`grep` had been silently returning nothing because it treated the file as binary); all five shipped files now scan clean at zero stray control bytes.
- 2026-08-16 | authoring content that embeds code + its claimed output | Verify claims against the SHIPPED artifact, re-extracted programmatically, never against the scratch copy you drafted from — and verify the pointers, not just the payload. Content formats that reference code by 1-based line number (annotations, callouts, footnotes) are hand-counted prose about a string, so they drift the moment you reflow the snippet, and nothing in a schema validator or `node --check` looks at them. Write a script that imports the real module, dumps each code block to a file, executes it, and prints every annotation's line number ALONGSIDE the line it actually resolves to; an in-range number pointing at a blank line or a loop header is the common failure and reads fine until someone follows it. Same principle for authored length budgets: measure with the tool the spec names rather than trusting the draft to feel right. | GRAPH-601 D3: the extract-and-run audit found one annotation at line 22 of a 21-line snippet plus three pointing at non-print lines, all invisible to `node tools/validate-lessons.mjs` (which passed); and `wc -w` put all six narration scripts over the documented 600-900 word cap (945/951/978/960/1013/969) when every one had felt in range while drafting.
- 2026-08-16 | authoring exercises/tests for an ISOLATION or LOCKSTEP property | A property of the form "A must not see B's write" is unobservable unless a participant actually READS the shared channel and reports what it saw — with inert participants, the correct implementation and the broken one emit byte-identical output, so the check passes vacuously and the warning in the instructions is enforced by nothing. Make one participant stamp the pre-step value into its own output, then assert that stamp. Same discipline as a negative control: mutate the runtime to merge early and confirm a NAMED check fails. | GRAPH-601 lab10: the super-step mutant (merge each node's update inside the frontier loop instead of after it) produced ZERO failing checks out of six, because neither parallel gatherer read `state["notes"]`. After both gatherers began emitting `[notes_at_start=len(state['notes'])]`, the same mutant failed two named checks; final sweep 7/7 mutants killed across six labs.
- 2026-08-16 | authoring content that pastes program output verbatim | Hand-transcribed "verified output" drifts silently, so audit it mechanically: extract every claimed-stdout comment from the source, set-match it against the real interpreter's stdout, and run a negative control (a deliberately altered digit) to prove the matcher bites. Two failure shapes only the audit finds — whitespace drift inside a formatted line, and comment lines that present an INPUT as though it were printed output when the snippet never printed it. | GRAPH-601 D2: 8 of 64 claims failed the first audit (`resolve    9` vs the real `resolve   9`, plus three Cypher query strings shown as output that the loop never printed); after fixing the snippet to print what the comment claimed, 61/61 matched, with `hops 5 -> 0.445` / `reduction: 1011x` correctly rejected and their true values accepted.
- 2026-08-16 | integrating real content into a component library inherited from a working upstream | CSS copied byte-for-byte from a healthy oracle is only validated against the ORACLE's content, so run the layout gate against yours and read the width signature as a diagnosis: overflow that persists at the WIDEST width is an unbreakable token (a URL in `<code>`, or a slash-joined run — browsers do not break on `/`), not a responsive bug, and the fix is `overflow-wrap: anywhere` on the list item rather than a media query. The nastier sibling is silent: a fixed-height box with `overflow: hidden` (needed for a 3D flip or a clipped card) TRUNCATES overlong content with no scrollbar and no error, so the learner reads half an answer and nothing in the DOM or console says so — assert on `scrollHeight > clientHeight` for every `overflow:hidden` element, not just on horizontal spill. | GRAPH-601 integration: `tools/audit-layout.mjs` reported 22 problems on first run over 20 routes; `comprehensiveness/diversity/empowerment` overflowed a D3 card by 19px at 1440px and 11px at 390px (wider = worse, the tell), lab prereq `curl …/lab01_graph_anatomy.py` overflowed by 156px at 390px, and two D4 flash-card backs were cut off by 11px inside a 130px `.fc-card`. - 2026-08-17 | adding the Nth item to a pipeline that claims to be N-agnostic | A producer being genuinely generic is NOT evidence that its consumers are, and the consumer's hardcoded list fails SILENTLY in the worst way: the new item appears everywhere cheap to check and is unreachable only on the one path nobody re-tests. Enumerate the consumers separately from the producer and grep each for a literal list of the existing ids — build config, UI pickers, test fixtures, usage strings.

- 2026-07-27 | headless game/engine build | An init-order-dependent self-registration (`Instance = this` in Awake, read by another component's Awake) fails silently and still renders correctly; resolve manager singletons lazily on first access instead, and have the verification harness read a counter back through the same reference the game uses so the null is observable. | Star Salvage combat harness logged `shots=0` while bolts were visibly in flight; after lazy resolution it logged 113 shots over 45 s against a configured 2.5/s.
- 2026-07-27 | verification scripting | A shell assertion that EXTRACTS a value before comparing it has two failure modes, and only one is safe: `awk -v pat='^\[Tag\]' '$0 ~ pat'` silently becomes the character class `^[Tag]` because awk strips the backslashes when building the string, so extraction returns 0 against a log that plainly contains the lines. Match by literal prefix (`index($0, prefix) == 1`), and prefer assertions whose broken-extractor value FAILS (`-gt 0`) over ones where it passes (`-eq 0`). | Star Salvage `tools/verify-states.sh`: wave/kills/salvage all read 0 from a log showing `[Wave] start n=3` and `kills=33`; literal-prefix matching returned 3/33/64.
- 2026-07-28 | game-balance / autonomous verification | A verification bot that plays the game is an INSTRUMENT and must be calibrated against an anchor it is not being used to test, or its measurement is unfalsifiable. A frame-perfect pilot answered "where does an oracle die", not "where does a player die", and reported a difficulty target as passing/failing arbitrarily; adding a human-cadence reaction delay tuned against the design doc's INDEPENDENT median-player expectation made the same probe reproduce two separate documented anchors and then measure the target honestly. | Star Salvage: pilot at 60 Hz reached wave 20/300 s at mid-tier; at 0.22 s cadence, zero upgrades reproduced §1's "wave 4-6 in 60-100 s" (wave 5/71 s, wave 6/95 s) and §4.1's "~140 salvage in ~90 s" (140), after which the mid-tier number was a prediction rather than a fitted result.
- 2026-07-28 | tuning a constant toward a requested target | Two checks before spending rungs, both of which changed the answer here. (1) Is the target JOINTLY FEASIBLE with the hard limits already asserted? Quantities derived from one underlying value cannot be set independently, so a target can be reachable and unshippable at once. (2) Never pick the setting from the small calibration sweep — re-measure the candidate at the gate's own sample size, because a sweep that is only precise enough to rank settings can rank them wrongly. | Star Salvage: income and pickup-miss are both functions of `banked = dropped x (1 - miss)`, so reaching the `[90,150]` income band drove worst-case miss to 38.7-39.1% against a hard 40% ceiling at two of four settings. A 3-sample sweep read `ScrapFallSpeed` 2.5 at income 190 and 3.5 at 174 and would have selected 3.5; the 9-sample gate reversed it (2.5 -> 152) and 2.5 was also 15 points better on ceiling margin. Evidence: `docs/balance-gate-1.0.0.txt`, `tools/balance-gate.sh --repeats 3`.
- 2026-07-28 | game-balance / measurement harness | Before treating a target band as missed, re-measure the BASELINE the band was derived from, and measure the same cell twice. A documented pre-change number can fail to reproduce for two independent reasons — an uncontrolled input (the probe never pinned the ship, so it flew whatever the previous harness persisted) and an instrument whose own run-to-run spread exceeds the band's width (a variable-timestep run is not reproducible just because its RNG is seeded). Either one makes "we missed the band" an unsupportable claim. | Star Salvage: pre-retune t0 re-measured at wave 8/9/6 on a clean Vanguard vs a documented 5; two identical 9-run gates measured Tmax/seed-7 at wave 20 then 13.
- 2026-07-28 | analytics/slicing layer over free-text historical data | Before trusting any slice, enumerate the DISTINCT raw values of each parsed field from the real corpus and check two things the unit tests cannot see: what fraction the parser silently buckets as unknown, and whether any bucket rule matches a string that names a category and disclaims it in the same breath. A field that is 13% unknown reads as a sparse axis, not a broken parser; a first-match-wins bucketer manufactures signal out of a disclaimer. | job-sweep decision data: 14/110 records carried a `~25 d` age the leading-days regex rejected on the tilde and dropped to `unknown` (all 110 band after allowing the source's own approximation marker); and 21 rows reading `Hybrid / workplace type not stated in public guest result` would have counted as `hybrid` unless "not stated" is tested before every other token. Coverage measured by re-running the parsers over the written ledger, not over fixtures.
- 2026-07-28 | HTTP handlers that abort a request mid-upload | When a server responds and then destroys the socket (413 on a body cap, 429 mid-stream), it MUST also send `Connection: close`. A keep-alive client returns the already-dead socket to its pool, so the failure lands on the NEXT, unrelated request as an opaque "socket hang up" — the test that breaks is not the test for the code you wrote, which sends you debugging the wrong handler. Ordering matters too: write the status first and destroy only after the response's `finish` event, otherwise the client gets a reset with no status at all. | dy-bridge `readBodyCapped`: the 413 assertion passed while the following POST died; adding `Connection: close` to that one response fixed it, and a browser would have hit the same thing.
- 2026-07-28 | adding a network call to an existing static page | Read the page's own `Content-Security-Policy` BEFORE writing the fetch, and prove the policy edit is load-bearing with a negative control that serves the original policy. A `default-src 'self'` with no `connect-src` blocks every cross-origin fetch, and the block surfaces as the feature's own error path — a plausible-looking "couldn't reach the server" that sends you debugging the request code, the server, and CORS, none of which are wrong. The control also exercises the error path for free. | job-sweep page: with the original CSP the bridge request never reached the network layer (Playwright's route handler never fired) and the page fell to its error banner; adding `connect-src 'self' https://bridge.dyuhaus.com` made the same run reach `s-ok`. Evidence: `csp.js`, 8/8, both directions asserted.
- 2026-07-28 | verifying a fix whose symptom is a POSITION, SIZE, or ACCUMULATED value | When the observable is a number that drifts over time, a passing assertion is worth nothing until you prove the number was somewhere else first. Add a SETUP assertion that fails if the quantity never moved, and pick the sampling moment by waiting for a displacement rather than for a clock — a fixed delay can land exactly where a fixed build and a broken one agree, because a value restored to X and a value drifting through X are indistinguishable at that instant. Then run the probe against a build with the fix reverted; if it still passes, it was measuring nothing. | Star Salvage planet reset: the floor ceremony leaves the planet ~4 units ABOVE its start and drift carries it back DOWN THROUGH that position ~12 s later, so a hard-coded wait was a coin flip; waiting for `|y - start| >= 2` instead made the reverted build fail at dy=3.390 while the fixed one read dy=0.000. The same reverted-build control on a saturating-add fix printed the whole failure — `scrap=-2147483159` clamped to `0`.
- 2026-07-28 | new branching/gating logic + its tests | When a freshly written suite for new decision logic goes green on the FIRST run, it has not yet been shown to test that logic — fixtures can pass because the code path was never entered. Mutate each gate independently (disable it, invert its ordering key, widen its input set) and confirm a named test fails for each; a gate whose mutant stays green is untested, and the mutants also reveal which test is load-bearing for which rule. | job-sweep confound checks: 38 tests passed immediately; 5 mutants (confound gate always-pass, policy gate off, decision-axis exemption removed, suppressed-may-explain circularity, smallest-slice-first ordering) each failed exactly the intended tests — the circularity and ordering rules turned out to rest on a single test, which is worth knowing before touching it.
- 2026-07-28 | defensive guards and repair paths | When the observable is "the system NOTICED something", assert the LOG LINE, not the resulting value — a guard that repairs quietly and a guard that never fires leave identical state, so a value-only assertion passes against both. The corollary is a code smell worth hunting: a defensive clamp added at a PARSE boundary can silently destroy the evidence a later repair path exists to produce, which is the original bug moved one function earlier rather than fixed. | Star Salvage v3: `SaveData.AdoptStringTotals` clamped a negative wallet on the way in, so `Normalize` never saw one to repair and `[Save] REPAIRED` never printed; every value assertion still passed (the bank read 0, which is also the correct repaired value). Caught by `verify-states.sh overflow` asserting `grep -q '^\[Save\] REPAIRED'`. Fixed by making parsing raw and repair loud, verified by the same grep going green.
- 2026-07-29 | inheriting a "verified" branch / post-gate polish | Re-running the verification suite on the FINAL artifact is not a formality even when every script passed on an earlier build — diff what changed between the two builds and ask which assertion is sensitive to it. A calibration constant is the highest-risk kind, because it moves player capability and therefore every rate downstream of it, including ones nobody associates with balance. Confirm the attribution by finding a log field whose ratio between the two builds equals the constant's change exactly. | Star Salvage v3: the sector-100 soak passed on the 16:27 build and failed `no pool outgrew its prewarm` on the 18:06 one (scrap 88 -> 93/94/90, 3 of 3). The enemy side was identical to fifteen figures while player damage and hull both read 1.771561x = exactly 1.10^6, the six levels SteadyOffsetDamage/Hull had gained at 18:02 — proving the calibration, not v3's scaling, raised airborne-salvage occupancy. The pool's own derivation (one capped wave = 88) ignores that a 5.0 s wave window overlaps a 9.6 s fall time.

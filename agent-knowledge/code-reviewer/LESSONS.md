- 2026-07-29 | live-infra rename review | Two candidate findings in one review were artifacts of the evidence-gathering step, not the code: grep -o of <link> tags made commented-out stylesheets look active (raw file read showed the <!-- -->), and a probe loop that prepended the host to already-absolute hrefs produced false 404s on pages that were live-200. Before reporting, re-verify any extraction-based evidence (grep -o, generated probe loops) against raw file content and a hand-built request. | verified via sed -n on index.html + direct curl of each URL
- 2026-07-29 | credential/identity toolchain review | When reviewing wrappers that inject a machine-account identity, do not stop at the code paths: verify the STORED identity data against the remote's actual attribution (git log author emails on the branch, then `gh api repos/<owner>/<repo>/commits/<sha> -q .author.login`). A valid token paired with a wrongly-registered author email silently reattributes every commit to the human account while every script "works". Also empirically test fail-open on empty (not just missing) credential files — `gh` treats empty GH_TOKEN as unset and falls back to the ambient login. | validated: git credential fill with/without helper reset + commits API on homelab PR 12
- 2026-07-31 | autonomous-gate branch review | When one state bucket starts holding two kinds of entry — a positive de-dupe marker ("we announced/merged this") and a negative one ("we evaluated this silently") — check every writer of the bucket for clobbering the other kind, and probe with a flip-flop input at a FIXED key (e.g., checks pending→green at the same head) run against both the branch and the pre-change build. A silent-refusal recorder that overwrote notified/autoMerged markers re-enabled duplicate notifications and a second merge attempt, while the suite's own "repeat tick" dedupe test passed because it never flipped the input. Also: when a branch is amended mid-review, re-baseline (rev-parse + md5 of analyzed files) and re-run the repros before reporting. | repro scripts driving relay.run() through the project's own stubbed harness, branch vs origin/master control
- 2026-08-07 | autonomous-gate ladder review | When a timed state-machine action (a 14-day expiry close, a clock tick) lives behind a de-dupe/short-circuit hook, trace EVERY early `continue`/`return` that precedes the hook — the clock is only as reachable as the earliest guard above it. Here the 14-day auto-close ran only inside the `already_head==head` de-dupe branch, itself gated behind a `checks != ready` and an `isDraft` early-continue, so an awaiting PR whose CI flips to pending (the code's own suppress-state comment admits scheduled workflows re-attach runs at an announced head) never re-evaluates its expiry. Errs safe (no merge) but silently breaks the stated liveness guarantee, and the whole test suite missed it because every expiry fixture held checks GREEN across the wait. Probe timed hooks with the guard-tripping input (non-ready checks / draft), not just the happy path. | verified by reading the run-loop guard order (pr_relay.py checks-guard before ladder_maintenance) + fixture inspection (_await_human uses self.GREEN throughout)
- 2026-08-07 | Compose UI branch review | A hold-to-repeat pattern (`detectTapGestures(onPress = { fire(); val job = scope.launch { while(true){ fire(); delay(..) } }; tryAwaitRelease(); job.cancel() })` with `scope = rememberCoroutineScope()`) is only safe while its `pointerInput(key)` never restarts mid-press: coroutine cancellation rethrows out of `tryAwaitRelease` (decompiled TapGestureDetector catches only GestureCancellationException), skipping `job.cancel()`, while the composition-scoped job survives and `rememberUpdatedState` repoints `fire` at whatever key now occupies the slot. Any diff that makes such a key DYNAMIC (e.g., swapping a keycap row in place) turns the latent leak into a runaway-input bug — check every `pointerInput` key that a new piece of state can now change. | verified via javap on foundation-release classes.jar (PressGestureScopeImpl.tryAwaitRelease bytecode) + positional-memoization reasoning on the row swap
- 2026-08-07 | auth-gated endpoint review | Two techniques earned their keep: (1) when `git diff origin/<base> --stat` lists a file the worktree never touched, run `git merge-base` before reporting — a stale branch base shows the base branch's own commits REVERSED in the diff, and mistaking that for a hidden change (or worse, a reverted fix) is a phantom finding; (2) to prove an auth gate rather than infer it, plant a secret marker in the protected resource, then assert the marker is absent from EVERY unauthenticated response across variants (bad/absent bearer, valid token in a cookie instead of the header, trailing slash, double slash, percent-encoded path, case change, HEAD/method confusion) plus one authenticated control that DOES return it — status codes alone can't distinguish "blocked" from "route never matched". | ephemeral bridge.js instance + throwaway tmux session, probe script asserting marker absence across 9 unauthenticated variants
